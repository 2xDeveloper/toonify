# Toonify

Upload a photo, get a caricatured cartoon character, and preview it printed on
a t-shirt, mug or phone case. Everything runs in the visitor's browser — no
backend image processing, no generative AI service, no upload, no per-image
cost. The photo never leaves the device.

## Getting started

```bash
npm install
npm run dev      # http://localhost:3000
```

Other scripts:

| Script              | What it does                                  |
| ------------------- | --------------------------------------------- |
| `npm run build`     | Production client + SSR build into `dist/`    |
| `npm start`         | Serves the production build                    |
| `npm run typecheck` | `tsc --noEmit`                                 |

Node 22.12+ is required (a TanStack Start v1 constraint).

## Stack

- **TanStack Start v1** with file-based routing via **TanStack Router**
- **React 19** + **TypeScript**
- **Tailwind CSS v4** through `@tailwindcss/vite`, themed in `src/styles.css`
- **Vite 7**, **Lucide** icons, Outfit + Figtree from Google Fonts
- State is plain `useState` — no store library

## How the cartoon is made

`toonify(file, options, onProgress)` in `src/lib/toonify.ts` runs five stages,
all on the visitor's device:

1. **Decode and downscale** to 760px on the long edge, honouring EXIF rotation
   so phone photos aren't processed sideways. The untouched downscale is
   emitted through `onProgress` right away so the mockup fills in immediately.
2. **Measure the face** with MediaPipe Face Landmarker — 478 points per face,
   up to six faces. This is a measurement step, not a generative one: it
   reports where the eyes, mouth and jaw are.
3. **Exaggerate** those features (`caricature.ts`). Radial handles anchored to
   the landmarks inverse-map each pixel, enlarging eyes, widening the grin, and
   shrinking or extending the jaw. This is the step that separates a caricature
   from a filter.
4. **Stylize** (`cartoonFilter.ts`): Kuwahara smoothing, extra skin flattening,
   cel-shaded lighting bands in HSV, and adaptive ink outlines.
5. **Compose**, in character mode: cut the head out along the face oval
   (expanded upward for hair, feathered at the edge) and set it on a
   hand-drawn body from `bodies.ts`.

If no face is detected the app degrades gracefully to stylize-only and tells
the user, rather than failing.

### Styles

Each style drives both the exaggeration and the paint.

| Style              | Eyes | Nose | Smile | Chin | Look                          |
| ------------------ | ---: | ---: | ----: | ---: | ----------------------------- |
| Cute Toon          | 1.50 | 0.78 |  1.20 | 0.84 | Big eyes, soft round jaw      |
| Big Grin           | 1.28 | 1.34 |  1.50 | 1.08 | Goofy party caricature        |
| Classic Caricature | 1.32 | 1.22 |  1.34 | 1.14 | Fair-booth artist             |
| Anime              | 1.66 | 0.70 |  1.06 | 0.86 | Oversized eyes, clean line art |

Because overlapping handles compound slightly, effective magnification runs a
little above or below these numbers; they are artistic dials, not exact ratios.

## Licensing (important for resale)

This app is built to be shipped in a product you sell:

- **MediaPipe** (runtime + face landmarker weights) is **Apache-2.0**, which
  permits commercial use.
- The **cartoon bodies** in `src/lib/bodies.ts` and the whole filter pipeline
  are original work in this repo — no third-party asset licence attaches to
  the output.
- **AnimeGANv2 was deliberately not used.** Its upstream licence restricts the
  model to non-commercial purposes and requires an authorization letter for
  commercial use. The popular PyTorch port is MIT, but that covers the code,
  not the weight lineage.

`npm run sync:mediapipe` (wired into `predev` and `prebuild`) copies the WASM
runtime out of `node_modules` and downloads the model into `public/mediapipe`,
so production serves both from your own origin instead of Google's CDN. The
app falls back to the CDN only if those files are missing.

## Cost at scale

Every stage runs in the visitor's browser, so serving one cartoon and serving a
million costs the same: nothing beyond static hosting. There are no API keys,
no per-image fees, and no image ever leaves the device.

## Mockups

`ProductMockup` draws one of three SVG templates and tints it with the selected
hex color. Generated art is layered over the print area in an absolutely
positioned element using `mix-blend-mode: multiply`, so it reads as ink on
fabric or ceramic rather than a sticker. While the heavy pass is running the
art is blurred instead of swapped out, which keeps the preview from flashing.

## Not built yet

- **Cart and checkout.** "Add to cart" is intentionally disabled — there is no
  cart state, payment provider, or order storage.
- **Accounts and saved designs.** Nothing persists across a refresh.
- **Bespoke poses.** Bodies are drawn templates, so users pick from the set in
  `bodies.ts` rather than getting a unique pose per photo. Inventing a pose
  from a chest-up photo is a generative problem, not a filtering one.
